# VAELORA V1.1 — Jordan outdoor planner

## Product and architecture

Continued the current working tree, preserving the original engine, reviewed dataset,
Open-Meteo adapter, Groq provider configuration, grounding checks and near-tie policy.
The V1.1 page now mounts `PlannerApp`, with `PlannerResults` and the existing MapLibre
integration. The previous UI files remain preserved; scoped `planner.css` applies the
new sporty product identity without discarding the earlier visual work.

- Jordan positioning, with explicit Greater Amman-only production coverage.
- `coverage.ts`: country → supported city → reviewed area IDs; adding a registry
  entry alone does not enable an unsupported city's recommendations.
- English/Arabic dictionaries and translated descriptions for all 11 production
  areas. Language persists in localStorage; first visit uses browser language.
  The document and interface switch between RTL/Arabic and LTR/English.
- Compact Ask planner near the hero, three suggested prompts, and three quick
  journeys: nearby now, plan a run, plan a walk. AI results enter the same cards,
  map, hourly outlook and collapsed factual trace as manual recommendations.
- Manual reference areas, optional browser geolocation, favorites and recent
  activity. Coordinates remain in component state, not localStorage, API payloads
  or LLM messages. Denial/timeout clears stale coordinates and leaves planning usable.
- Haversine distances use mean Earth radius 6371.0088 km. Only the existing leading
  match band is reordered by proximity; membership, scores, activity fit, hard
  constraints, weather and best windows are unchanged. Distance is explicitly
  approximate/straight-line, never road distance or travel time. A reference area
  is not represented as the user's exact position. A >50 km nearest-area gap
  triggers an outside-local-coverage notice, not a claim of polygon verification.

## Honest duration and weather support

30/60-minute choices check one complete forecast hour; 90 minutes checks two.
The agent also supports explicit minute durations such as 45 minutes using an
optional `durationMinutes` field. Conversion is deterministic and disclosed.
Fractional clock bounds and route-distance guarantees remain unsupported.
The engine itself still validates whole-hour requests and calculates best windows.
`hourlyAssessments` is an additive response field calculated with the same scorer
and constraints as the recommendation pipeline, not a separate frontend score.

`POST /api/agent` accepts an optional validated `locale: "en" | "ar"` alongside
`prompt`. Existing prompt-only clients remain supported. Arabic final presentation
is rendered from deterministic facts and translations; the model still only calls
the existing intent and presentation tools. No free-form model reasoning is shown.

## Visuals and assets

Navy, sandstone, desert sand and ivory remain the core palette, with a restrained
olive accent. Typography is smaller and more functional; controls and result cards
are designed for scanning rather than editorial display. Motion remains CSS-only,
with pause and reduced-motion support.

The hero terrain/sun/contour SVG is original inline artwork created for this project.
It evokes Jordanian terrain without identifying a particular activity area. It is
decorative, not evidence, a route, or a geographic survey. No external photography,
stock-image downloads, hotlinks, new font services or third-party design bundles
were added. OpenStreetMap raster tile attribution is retained; tile labels may
contain native-language proper names independently of the interface language.

## Verification and limitations

74 repository tests (including seven new V1.1 tests), 28 offline evaluations,
dataset validation (35 researched, 11 production), TypeScript and lint passed.
The production build passed using the documented `next build --webpack` fallback on
Windows. The final preview uses `next dev --webpack`. No deployment is authorized.

Language smoke checks are bounded, not a broad Arabic language benchmark. Raster
maps and weather require network access; forecasts do not measure park microclimates.
No routes, opening-hours guarantees, safety guarantees, verified shade, accessibility
or air-quality assessment were added. Only current Greater Amman production areas
are returned. Favorites and language preferences are device-local and may be lost
when browser storage is cleared. Browser QA was Chrome, not a cross-browser lab.
Third-party local `.agents/` tools and existing `AGENTS.md` changes are preserved
outside the product commit. `.env.local` remains ignored and untracked.
