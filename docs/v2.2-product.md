# V2.2 — Final Product Experience

V2.2 builds on the existing V2.1 implementation. It preserves the deterministic
weather and recommendation pipeline, reviewed-place boundaries, local GPS engine,
IndexedDB history, GPX export and grounded AI contracts. No locations, coordinates,
authentication, cloud profile storage or unrelated activities were added.

## Experience and architecture

- Semantic tokens in `src/app/tokens.css` define graphite surfaces, citrine activity
  emphasis, cyan route information and violet AI accents. Light, dark and system
  appearance share the same components. Score colors supplement numeric scores
  and text labels, rather than replacing them.
- Home prioritizes the activity score, Best Window and Start Activity. Planning
  tools remain available below the primary decision. Track retains its existing
  lifecycle and GPS calculations with clearer live, paused and finished states.
- Optional two-step onboarding supports English and Arabic from the first screen.
  A name is optional; skipping persists. A guest profile stores only a display
  name, preferred activity/duration, locale, theme and onboarding completion.
- `guest-profile.ts` validates this versioned data and calculates finished-activity
  totals. Walking and Running pace statistics remain separate. Unknown properties
  are excluded; names reject control characters and render as escaped text.
- Profile exposes local totals, per-activity statistics, recent activities, saved
  areas and preferences. Recent activity opens the existing Track summary. History
  changes update Home and Profile through a local event after IndexedDB commits.
- Clear history, clear profile/preferences and reset local app data have distinct
  scopes and explicit confirmation. They preserve unrelated browser storage and
  are disabled during recording or a paused session. Clearing only the profile
  preserves activities and saved areas.
- Native dialogs provide focus containment, Escape dismissal and focus restoration.
  Logical layouts, Arabic labels and metric units support RTL. Map zoom/compass
  labels are localized, and route colors/markers remain legible. Mobile layouts
  accommodate the bottom navigation and safe area. Reduced motion is respected.
- The PWA retains its public offline shell; updated manifest colors and raster icons
  match the identity. API responses and GPS records are not put in service-worker
  caches. GPS/history remain device-local; GPX is an explicit precise-route export,
  while the share image contains summary information without a route.

## Remaining limits

- Foreground browser recording is supported; background/locked-screen GPS is not
  guaranteed. Physical-device field accuracy and OS installation prompts still
  need device testing. Offline maps require already available tiles.
- Profiles, drafts and history are device-local and can be lost when browser data
  is cleared or evicted. There is no account, cloud backup or cross-device sync.
- Weather and place recommendations depend on live forecasts and reviewed coverage;
  a high single-hour score does not guarantee a complete suitable outing window.
  Empty recommendations remain explicit. Existing provisional scoring policies
  and dataset uncertainty remain unchanged.
- Single-tab recording is the intended usage. No multi-tab recording coordination
  or continuous background tracking was introduced in this visual/product phase.

No deployment was performed.
