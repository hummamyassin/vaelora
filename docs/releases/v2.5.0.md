# VAELORA v2.5.0 — Modern fitness experience release

**Released:** 26 October 2026 · **Production:** [vaelora-chi.vercel.app](https://vaelora-chi.vercel.app) · **Tag:** `v2.5.0`

## Summary

v2.5.0 turns VAELORA from a planning website into a fitness product built around the VAELORA V icon. Planning now leads with a single Score and a clear decision. Recording survives real outdoor conditions better, Home remembers where you plan from, and the public deployment gains edge rate limiting with a safe on-device mode for Ask. The full list is in the [CHANGELOG](../../CHANGELOG.md#250---2026-10-26).

## Product changes

- **Home**: a Today module with the ten-segment VAELORA Score ring, a plain decision, the best window and an hour-by-hour comfort strip. When today has no complete window left, it falls back to the next good window tomorrow.
- **Remembered area**: a returning visit opens on the last planned area. GPS is stored only as a coarse ~2 km forecast cell.
- **Track**: a dark full-screen recorder with a plan dial. Keep Awake is on by default, and an alert offers to resume after the app is backgrounded or the screen locks.
- **Summary, Share, Progress and Profile**: a new recap and share cards, real weekly progress with an active-day ring and distance chart, and all-time stats.
- **Map and Ask**: restyled. Ask works in an on-device mode when live AI is not enabled.
- **System**: one Phosphor icon set, light and dark themes, full English and Arabic RTL coverage, and hash routing that makes Back and refresh behave like an installed app.

## Engineering changes

- The token-based V2.5 design system (`src/app/styles/tokens.css`) replaces the metallic material layer. `ScoreRing` and `ProgressRing` are shared components.
- The wake lock and visibility handling in the recorder pause honestly instead of recording a gap.
- `src/lib/plan-place.ts` is a strict parser for the remembered area: it refuses precise fixes and data outside the service area.
- The discovery response gains `tomorrow: { date, window } | null` from the existing two-day forecast.
- `src/server/edge-limit.ts` applies one Vercel Firewall rule (`vaelora-api`) to every route. AI fails closed; the other routes fail open.
- CI on pull requests and pushes to `main` runs tests, lint, typecheck, dataset validation, the offline AI replay and the production build.

## Security and privacy

- One edge rate-limit rule covers all API routes, and in-memory budgets remain as a secondary guard.
- Live public AI needs the published firewall rule **and** `VAELORA_AI_PUBLIC_ENABLED=true`. Until both are in place, Ask stays on-device and makes no request to `/api/agent`.
- Routes, history and precise GPS stay on the device. They never reach the AI provider and never appear in URLs.
- See [production security](../production-security.md) for the activation steps.

## Known limitations

- **Background GPS is not guaranteed.** Browser and PWA recording is foreground-only. When the app is backgrounded or the screen locks, the session pauses and asks to resume, especially on iOS.
- Coverage is limited to Greater Amman's reviewed places. Weather is regional forecast data, and AQI is not assessed.
- Activities are device-local. Use the JSON backup to keep a copy.
- Physical-device field testing (GPS accuracy, battery, install prompts) is still outstanding. A manual production smoke test from a network that can reach Vercel is recommended.
